## 1. System Overview

### 1.1 Application Description

Eidet is a local-first long-term memory service for AI coding agents. It provides persistent, semantic memory across coding sessions using a local RavenDB database (embedded or external), optional local LLM enrichment (Ollama or any OpenAI-compatible server, e.g. LM Studio), and exposes functionality through a REST API, MCP server (stdio + HTTP), CLI commands, and an embedded Web UI.

### 1.2 User Types

| User | Description | Access |
|------|-------------|--------|
| AI Agent (MCP) | Claude Code, Cursor, etc. connecting via MCP stdio or HTTP | Full tool access (8 MCP tools: 6 core + park/resolve) |
| AI Agent (REST) | Any HTTP client using the REST API | API key scoped (read/write/admin) |
| Developer (CLI) | Local user running `eidet` commands | Full access via CLI |
| Developer (Web UI) | Browser user at `http://localhost:19380/ui` | Read-only browse + admin actions |
| Ollama Service | Local LLM for optional enrichment | Receives memory content in prompts |

| Boundary | Description |

| **TB-4: Service ↔ RavenDB** | HTTP to external RavenDB or in-process embedded calls |

| Category | Examples | Sensitivity |
|----------|----------|-------------|

## 2. STRIDE Analysis

> **Controls:** each threat cites the OWASP ASVS 5.0 chapter (V1–V17) that addresses it, or the infrastructure control where ASVS coverage is thin (Repudiation, DoS). Target level: **L1** — Eidet is a local, single-user developer tool; its highest-classification data (API key hashes, backups) is protected by OS file permissions rather than multi-tenant controls.

### 2.1 Spoofing

| ID | Threat | Attack Path | Likelihood | Impact | Score | Control | Mitigation |
|----|--------|-------------|:----------:|:------:|:-----:|---------|------------|
| S-1 | API key interception | Attacker sniffs Bearer token over unencrypted HTTP on non-localhost network | 2 | 4 | **8** | V6, V12 | Auth only required for non-localhost by default. Localhost traffic not typically interceptable. For remote access, deploy behind TLS reverse proxy. |
| S-2 | Unauthenticated localhost access | Any local process can call the API without auth when auth is disabled (default) | 3 | 2 | 6 | V6 | By design — localhost-only binding assumed trusted. Auth can be enabled via `eidet api-key create`. |
| S-3 | MCP stdio spoofing | Malicious process hijacks stdio pipe to impersonate AI agent | 1 | 3 | 3 | V6; infra: OS process isolation | MCP stdio is launched by the AI client itself. Process-level isolation is the OS responsibility. Note: stdio transport bypasses `ApiAuthGate` entirely — auth applies to HTTP only. |
| S-4 | CORS-based credential theft | Malicious website makes cross-origin API calls using user's browser session | 2 | 3 | 6 | V3, V4 | API uses Bearer tokens (not cookies), so CORS `*` does not leak credentials. However, unauthenticated endpoints (health, status, UI) are accessible cross-origin. |
| S-5 | Auth guard bypass via env var | Attacker sets `EIDET_AUTH_REQUIRE_NONLOCALHOST=false` to disable network auth requirement | 1 | 4 | 4 | V13 | Requires ability to set environment variables in the service process — implies existing system compromise. |

**Countermeasures in place:**
- API key auth with SHA256 hashing and scope model (ApiKeyService.cs)
- Network binding guard refuses non-localhost without auth enabled (ServeCommand.cs)
- Default bind to `127.0.0.1` only (EidetConfig.cs)
- Cryptographically random key generation using `RandomNumberGenerator` (ApiKeyService.cs:19)

### 2.2 Tampering

| ID | Threat | Attack Path | Likelihood | Impact | Score | Control | Mitigation |
|----|--------|-------------|:----------:|:------:|:-----:|---------|------------|
| T-1 | Malicious pack import | Attacker crafts .eidet pack with forged importance scores, fake lineage chains, or memories targeting other repos | 2 | 3 | 6 | V2, V11 | Pack imports are assigned to `bundle:{packId}` layer (read-only), non-local memories de-boosted 0.8x in recall scoring. No signature verification on pack files. |
| T-2 | Config file modification | Attacker modifies config.json to change RavenDB URL (exfiltrate data), add malicious hooks, or disable auth | 2 | 4 | **8** | V13; infra: OS file permissions | Config file lives in user's AppData/home directory with OS-level file permissions. No integrity checking on config load. |
| T-3 | Unverified binary update | `eidet update` replaces the running binary from a remote source. Two flavors with different assurances: the **dotnet tool** path resolves from NuGet.org, the **standalone binary** path from GitHub Releases over HTTPS with no cryptographic signature check of our own. **Unattended dimension (v0.11.0)**: the update is now also reachable without a human — the `UpdateCheck` scheduled task can install a release at a configured local hour, so a compromise of the publish path reaches every opted-in machine on its own schedule instead of waiting for someone to type the command | 2 | 4 | **8** | V11, V12 | **Publish-side**: NuGet publishing uses OIDC trusted publishing from the release workflow (no long-lived API key to steal), and NuGet.org validates the repository signature on install — so the dotnet-tool path is authenticated end to end without a signature check of our own. The GitHub Releases path still has no GPG/checksum verification. **Unattended-side compensating controls**: automation is **opt-in** (`update.autoUpdate` defaults false, asked once in `eidet setup`); an **age gate** (`update.minimumAgeHours`, default 24) refuses to install a release younger than a day, which is the only fleet-level circuit breaker available given immutable releases — a bad build cannot be replaced in place, only superseded, so the window exists to publish the successor first; an **unknown publish date fails the gate** rather than passing it; the resolved version is **pinned** through to `dotnet tool update --version`, so the vetted build is the one that lands; a **SemVer comparison** (not string equality) makes a downgrade unrepresentable; **install-flavor detection** keeps the automation off container and standalone installs, which cannot self-replace; and `eidet update --rollback` reinstalls the recorded predecessor — exact and reproducible precisely *because* releases are immutable. Runs as the invoking user (`InteractiveToken`/`LeastPrivilege` in the registered task), so it grants no privilege the user did not already have. |
| T-4 | Backup tampering | Attacker modifies .eidetbackup manifest or contents | 1 | 3 | 3 | V11 | SHA256 checksum verified on restore (BackupService.cs:115). Tampering both data and manifest checksum in a consistent way requires understanding the format. |
| T-5 | Environment variable injection | Attacker sets `EIDET_RAVEN_URL` to redirect database traffic to attacker-controlled server | 1 | 4 | 4 | V2, V13 | Requires process-level env var access. No URL validation on config load. |
| T-6 | Memory content manipulation via API | Authenticated attacker stores misleading memories to poison agent knowledge | 2 | 2 | 4 | V2 | Write gate blocks secrets and low-signal content. Scope model limits write access. Quality dashboard detects anomalies. **Write-time conflict check (#37)** — a store whose hard stance contradicts a high-trust incumbent is quarantined (heavy recall de-boost, still stored) and recorded in the `poisonpatterns/*` log rather than silently accepted; a repeat attempt fast-paths to Rejected. |
| T-7 | Single-shot memory poisoning via pack import | Attacker crafts one Pack/Intake memory — especially a Procedure or Heuristic — that an agent recalls and acts on without it ever being echoed (MemoryGraft, trigger-free, single-shot — arXiv:2512.16962) | 2 | 4 | **8** | V2, V5 | **Provenance/trust tier** (`MemoryTrust`) — derived, never-stored trust factor gates retrieval weight. Pack/Reflection/Unknown float at 0.5, repo-file Intake at 0.7, Procedure/Heuristic at 0.7 (floors combine as `min`); only earned echoes lift a memory toward 1.0. A freshly-injected, never-echoed pack Procedure is held at 0.5 in recall scoring, below trusted first-party memories. **Intake split off the import floor (v1.19)**: it reads files already in the repo the agent is working in — the same bytes any tool call would read — so it is not the remote-import surface this floor exists to hold down, and holding it here made a repo's own documentation unreachable rather than merely lower-ranked (measured: hit@5 53% vs 94% for agent-stored facts, one exact-term case at rank 94 of 100, because the floor multiplies the *whole* fused score). **Accepted residual**: an attacker who can write a file into a tree the user intakes now seeds at 0.7 rather than 0.5 — bounded by T-16's controls (deterministic zero-LLM gate, full secret+signal gate per candidate, importance capped at ≤0.5), still below every first-party origin, and not the memory layer's weakest link, since the agent reads those same files directly. Pack import is unaffected and in fact tightened: because the intake tier now outranks Pack's floor, `provenance=intake` joins the clamped declarations. Import hardening: a pack's self-declared `provenance=` cannot escalate trust above the Pack floor — `MarkdownPackFormat` clamps any trust-raising declaration back to `Pack`, so an attacker controlling the pack bytes cannot self-assign first-party trust. **Scope of that floor (corrected, [#80](https://github.com/stevehansen/eidet/issues/80))**: the clamp only ever governed the *pack* surface, so the floor was NOT unconditional — until #80, any path that failed to establish provenance at all defaulted to a fully-trusted value and reached full recall weight without touching a pack (T-20). Provenance is now closed-world: everything this build cannot map to a known trusted origin — including `Unknown` and any undefined ordinal — lands on the same 0.5 import floor, and the insecure `_ => 1.0` fallback is gone rather than merely guarded, so the floor now holds by construction instead of per-surface. A memory's accumulated echoes also no longer launder a content rewrite: the derived commitment factor multiplies *after* the echo lift (T-15). **Contradiction hardening (#37)**: for the specific case where a pack/imported memory takes the *opposite* hard stance to a high-trust incumbent, the write-time `ConflictGate` now quarantines it (heavy recall de-boost) and logs the pattern, closing the "trust is a de-boost, not a cutoff" residual for the contradiction case. |
| T-8 | Provenance laundering via consolidation | Attacker injects a poisoned Pack/Intake observation, then relies on consolidation to fold it into a high-trust Insight (`Provenance=Consolidation`), erasing the low-trust origin (compression-amplified toxin) | 2 | 3 | 6 | V2 | **Consolidation carry-through** — a new insight derived from any untrusted source inherits the *least-trusted* contributor's provenance (not `Consolidation`), so the trust tier keeps demoting it. The boost path admits only trusted sources: untrusted matches can neither raise a trusted insight's importance nor contaminate its lineage. |
| T-9 | Feedback-driven memory suppression | Caller with feedback access (or any localhost caller when auth is off) repeatedly fizzles a *legitimate* Procedure/Heuristic — preferentially with `reason=incorrect`/`version_drift`, which triggers the steeper content-invalidating penalty (Importance −0.2 / Confidence −0.3 per fizzle) — to drive the ROI gate's recall de-boost and `RoiDecay` Importance demotion, suppressing a useful memory below recall threshold (the downward dual of T-7's poison-upward) | 2 | 2 | 4 | V2 | **Reversible by design** — `MemoryRoi` is derived (never stored), never forgets, and never mutates content; Importance floors at 0.05 (never zero) and `RoiDecay` only engages after `MinFeedback=3`, so suppression is gradual, not single-shot. A single echo back to parity restores full ROI and the next maintenance pass leaves the memory alone. Requires the same write/feedback trust boundary as T-6; append-only echo/fizzle counts feed the quality dashboard's high-fizzle check. |
| T-10 | Agent-context injection via loose ends | Attacker with `write:all` (or any localhost caller when auth is off) parks a malicious loose end. Park bypasses the signal gate (secret scan only — LooseEndService.cs:48), loose ends carry **no provenance/trust** (LooseEnd.cs has no `MemoryProvenance`/trust fields), and they surface **unconditionally**: wake-up slice injects the top-3 open ends by priority into every `eidet_context` call (MemoryService.cs:621-643), and recall ride-along matches by tag overlap (cap 3). `priority` was caller-controlled and unclamped, so the attacker's item sorted first. The entire T-7 trust-tier defense is sidestepped — a trigger-free instruction injection that renders at the top of agent context every session | 2 | 4 | **8** | V2 | Volume is bounded (wake-up cap 3 + 120-token sub-budget; ride-along cap 3) but content is not trust-gated. Secret scan runs on park (same `SecretScanRule` as the write gate). Promote-to-memory re-enters the full write gate (`MemoryServicePromotionAdapter` → `MemoryService.StoreAsync`). Same trust boundary as T-6. **Partially mitigated ([#77](https://github.com/stevehansen/eidet/issues/77), v0.10.0)**: `priority` is now clamped to 1–3 at the `LooseEndService.ParkAsync` choke point (covers MCP/REST/direct callers), closing the sort-to-top lever. **Still open**: apply the trust tier — or a provisional-until-touched hold — to wake-up/ride-along rendering so untouched loose ends are not injected unconditionally. |
| T-11 | Retrieval-weight skew via alpha-learning feedback | Feedback-capable caller (same boundary as T-9) issues ~20–40 crafted echo/fizzle events to push the per-repo learned alpha (lexical-vs-vector blend) to a clamp, degrading **all** recall quality in that repo — broader blast radius than T-9's single-memory suppression | 2 | 2 | 4 | V2 | **Bounded by design** — EWMA λ=0.1 with alpha clamped to [0.15, 0.85] at both learn time and read time (MemoryService.cs:32-34, 485-489), so neither retrieval arm can ever be fully muted; worst case is quality degradation, not denial. Server-side atomic EWMA patch prevents lost updates. Reversible — normal genuine feedback re-converges alpha. |
| T-12 | Recall injection via forged memory links | Attacker with `write:all` attaches a `MemoryLink` from a legitimate high-scoring memory to a poisoned low-trust one (`POST /api/eidet/{id}/links` validates neither target existence, nor same-repo, nor ownership — MemoryService.cs:313-340); graph-neighbor expansion then pulls the poisoned memory into the recall candidate pool riding the parent's fused score | 2 | 3 | 6 | V2, V8 | Neighbors pass the **same** trust × ROI × non-local de-boost loop as direct hits, judged on their **own** metadata — parent trust does not transfer (MemoryService.cs:435-461). Expansion capped at 5 neighbors, 1 hop. Recall-time scope recheck on the loaded entry's actual `RepoId` neutralizes forged cross-repo links (MemoryService.cs:536-539). Residual: trust is a multiplicative de-boost with **no absolute cutoff**, so a strongly-linked 0.5-trust neighbor can still rank into a small result pool. |
| T-13 | Steering via forged negative knowledge | Attacker (same write boundary as T-6) stores a `Refuting`/`Cautionary` memory — via the `negative:true` sugar or an explicit `valence` on `eidet_store` / `POST /api/eidet` — asserting that a *correct* approach "does not work". When `type` is omitted the sugar defaults it to the near-immortal, L1-visible **Heuristic** lifecycle, and it renders with a ✗/⚠ warning glyph, so a false dead-end steers the agent *away* from a valid path and resurfaces every session | 2 | 2 | 4 | V2 | Same write trust boundary as T-6; content still passes SecretScanner + SignalGate. `MemoryTrust` still applies — a never-echoed agent-inferred Refuting Heuristic floats at the 0.7 provenance floor (not full trust), and `MemoryRoi` demotes it if it keeps being recalled-but-unused. The ✗/⚠ glyph surfaces the stance *as a warning*, not as asserted fact. **Write-time conflict gate (#37) — the direct control**: a forged `Refuting` memory whose content near-duplicates a high-trust `Affirming` incumbent is exactly the `ConflictGate` trigger (opposite hard signs + incumbent trust ≥ 0.9); it is quarantined (heavy recall de-boost, never hidden so a genuine correction can still earn its echoes), recorded in the `poisonpatterns/*` log, and a repeat attempt fast-paths to Rejected. An explicit supersession is exempt so the honest correction path is never penalized. Residual: negative knowledge is *designed* to surface prominently (Heuristic default + wake-up visibility), and the gate only fires against a high-trust incumbent — a false dead-end with no contradicted incumbent is still bounded by trust/ROI, not eliminated (the "sugar mis-classification" gotcha in `docs/domains/memory.md`). |
| T-14 | Reflector over-generation / trust-laundering | The ACE-style Reflector (`ReflectionEngine`, maintenance stage) makes the corpus's first LLM-driven *write*: one maintenance-time call synthesizes net-new memories from positive residue (net-echoed memories, Done loose ends, Contradicted verdicts). Two abuse shapes: (a) a compromised/hallucinating enrichment backend floods the corpus with fabricated high-value memories; (b) an attacker seeds poisoned residue (e.g. an echoed low-trust pack memory) hoping the Reflector folds it into a fresh `Provenance=Reflection` memory that erases the low-trust origin — the T-8 laundering pattern applied to synthesis, and a steering refinement of T-13 | 1 | 3 | 3 | V2 | **Ships dormant** — `ReflectionConfig.Enabled=false`; the stage no-ops until deliberately enabled *and* an enrichment backend is reachable. **Engine-owned trust fields** — the proposal schema carries content/type/valence/tags ONLY; `Importance` (0.5), `Confidence` (0.7), `Provenance`, and `DerivedFrom` are stamped by the engine, so the model cannot self-assign a trusted, high-importance lineage. **Provisional `Reflection` trust floor** — `MemoryTrust.ProvenanceTrust(Reflection)=0.5` (same tier as Pack/Intake), so a freshly-minted reflected memory is held below trusted first-party recall weight and must EARN trust via echoes. **Least-trusted stamping** — a reflection derived from any below-full-trust contributor inherits that contributor's provenance instead of `Reflection` (verbatim from consolidation carry-through, T-8), so laundering a poisoned source is blocked. **Mandatory `WriteValidator`** — unlike consolidation (whose text is pre-gated observation content), reflection runs the full secret+signal gate on the LLM-fresh text before storage. Volume bounded by the per-run `NightlyBatch` total cap (enforced across all residue arms, not per-arm) + the 0.85 near-duplicate suppression gate. Residual: an enabled Reflector still adds agent-inferred content the human never reviewed — bounded by the trust floor + ROI decay, not eliminated. |
| T-15 | Historical-version redaction alters an append-only node | The `RedactAsync` curation verb (#65, `POST /api/eidet/{id}/redact`) scrubs the content payload of a node — including a *superseded* one — mutating the append-only audit chain. Abuse shape: an authenticated caller redacts a node to destroy evidence rather than to erase a secret/PII | 2 | 2 | 4 | V2, V16 | **This is primarily the *mitigation* for persisted secret/PII in history** (the remediation path when a secret slips past the always-on scanner, or for GDPR erasure) — see the Information Disclosure control below. The tampering surface it introduces is bounded by design: redaction is **structure-preserving** (id, validity interval, `IsLatest`, lineage `ParentMemoryId`/`DerivedFrom`, echo/fizzle/access counters, RepoId, Type all kept — the chain stays walkable), **content-scoped** (only Content/Summary/OneLiner/ForesightHint/Entities are scrubbed to a `[redacted: {reason} @ {utc}]` tombstone), and **audit-tracked** (writes an immutable system observation recording who/when/why, mirroring Forget). Idempotent. Same write/API-key trust boundary as T-6; the endpoint honors existing auth scopes + the network-binding guard. **Citation-drift consequence ([#80](https://github.com/stevehansen/eidet/issues/80))**: because redaction keeps the id, every insight citing the redacted node still resolves *cleanly* while the citation now describes text that no longer exists — the chain stays walkable, but silently stops meaning what it meant. Nothing recomputed the id's content commitment, so this was indistinguishable from an untouched source. Now bounded: the id IS a truncated content commitment, `MemoryCommitment.Check` re-derives it on the read path, and redaction is discriminated **structurally, never by verb name** — `Render`/`IsAmendment` define one canonical `[verb: reason @ when]` shape that carries almost no knowledge, so forging it costs an attacker nearly all of the payload — the shape admits only a short single-line `reason`, which **bounds rather than closes** that channel (the stronger form, where a mismatch is legitimate only if a live system-sourced audit record cites the id, needs a reverse-`DerivedFrom` index and is recorded as the upgrade path in #80). A legitimate tombstone classifies as `Amended` (no trust penalty); content patched under a live id with nothing standing in its place classifies as `Broken` and is held at 0.25 in recall, applied *after* the echo lift so echoes can never launder it. The auditor's new `AmendedCitation` / `DanglingCitation` / `BrokenCommitment` checks surface all three as queryable findings. Those checks **fail independently**: resolving cited documents is deferred into the per-check isolation, so one unreadable cited document costs the two citation checks rather than aborting the run — previously it threw out of `VerifyAsync` before the isolation loop, silently taking the tamper detector with it, which is the worst possible failure direction for a detection control. A check that did not complete is flagged `ProbeFailed`, is absent from `ChecksProbed`, and surfaces on the quality dashboard as its own `integrity-unprobed` coverage row — never folded into a data-defect row, where an unrun read-path probe used to render as a Critical "N forgotten memories still reachable" about memories nobody had examined. And `/api/eidet/graph` now emits `GraphEdge.Status = Missing` rather than dropping an unresolvable citation edge — a dangling citation previously rendered as *no edge*, so the failure looked exactly like success. Consistent with the #37 downrank-never-hide rule, a broken commitment de-boosts and reports; it never hides. Residual: the check catches content patched under a *canonical* id, and an id `MemoryIdGenerator` never minted is deliberately reported `Intact` (a hand-built or foreign row must not masquerade as tampering), so an attacker who inserts a whole document and computes its hash correctly is undetectable by construction. Note also that there are **two** minting conventions — timestamped (default) and content-addressed (intake, so a re-imported file collides and skips) — and `MemoryIdGenerator.Matches` owns which preimages count, deliberately keeping that count out of the verifier. Accepting both does not widen the blind spot, since substituted content changes the hash under either; but a fourth caller minting ids by hand would once again read as tampering, which is why the format and its recognizer live in one class; the amendment shape is also a soft wire contract — an external tool writing tombstone content without `Render` reads as `Broken`. |
| T-16 | Memory poisoning via crafted commit messages | Attacker with commit access to a repo the user runs `intake-git` on (or a malicious upstream repo cloned and intaken) crafts Conventional-Commits messages that seed misleading Procedure/Insight memories — the T-6/T-7 pattern arriving through the new git-history ingestion boundary (TB-10) | 2 | 2 | 4 | V2, V5 | Deterministic zero-LLM gate (Conventional-Commits allowlist, merge/ADR detection, file-count threshold) bounds what is mined; every candidate passes the full `WriteValidator` secret+signal gate; provenance is the existing `MemoryProvenance.Intake` (deliberately NOT a new trust-bearing enum value), so git-seeded memories start on the provisional intake trust floor and cannot outrank first-party knowledge until echoed; per-commit skip reasons + `--dry-run` make every mined/skipped commit auditable. **Re-scored at v1.19** when that floor moved 0.5 → 0.7 (see T-7): held at 2×2. Likelihood is unchanged — it still requires the user to run intake over a repo they do not control. Impact stays in the same tier because nothing about what a seeded memory can *do* changed: it remains provisional (< 1.0, so it cannot outrank first-party knowledge), remains importance-capped at ≤ 0.5 by every extractor, and remains subject to the same deterministic mining gate. The delta is ranking position among untrusted candidates, not a new capability. |
| T-17 | Path traversal via memory-tool paths | Model-controlled `memory_20250818` paths (`/memories/../…`, url-encoded `%2e%2e`/`%2f`, backslashes) attempt to escape the `/memories` root — blob keys derive from the path, so an escape would read/write documents outside the caller's memory space (cross-repo or cross-collection tamper). Anthropic explicitly makes traversal protection the backend's responsibility | 2 | 3 | 6 | V5, V8 | **`MemoryPath` value type is the single choke point** (MemoryPath.cs) — every command binds paths through it at the transport boundary (`MemoryCommand.Parse`) and programmatic construction (`MemoryPath.Of`); it canonicalizes (collapses duplicate slashes, trims), enforces the `/memories` root, and rejects `.`/`..` segments, backslashes, control chars, and url-encoded traversal (recursively decoded). | T-18 | Rubber-stamp laundering via Canon approve | Canon P1 (#75) lets an Operator approve a synthesized (or UL-seeded) draft into a trusted `canon:*` `Insight`. **Countermeasures in place:**
- Write gate with SecretScanner (13 patterns) and SignalGate (WriteGate.cs)
- `MemoryPath` canonicalization + `/memories` root enforcement on every memory-tool command; per-instance repo binding in `MemoryToolTranslator` (bounds T-17)
- Pack imports isolated to read-only layers with de-boost scoring
- Graph-neighbor expansion runs *before* the trust/ROI/de-boost loop so neighbors get identical downstream gating; scope recheck on actual `RepoId` blocks forged cross-repo links (bounds T-12)
- Per-repo alpha clamped [0.15, 0.85] at learn and read time — the compensating control for shipping alpha-learning (bounds T-11)
- Loose-end park runs the same `SecretScanRule` as the write gate; promote-to-memory re-enters the full gated funnel (partial bound on T-10)
- Provenance/trust tier (`MemoryTrust`, MemoryTrust.cs) — derived per-recall trust factor gating retrieval weight; deterministic, local, always-on; no stored field to forge
- Closed-world provenance (`MemoryProvenance.Unknown`, #80) — the field initializer, `ProvenanceResolver`'s unrecognized-source arm, and every failing deserialization branch (empty / unparseable / `!Enum.IsDefined`) all resolve to `Unknown`, which shares the 0.5 import floor EXACTLY; `ProvenanceTrust` enumerates the trusted origins and its former `_ => 1.0` fallback is removed, so the safe default is no longer the insecure one. `ProvenanceRules.IsTrusted` excludes `Unknown`, so a synthesis over legacy memories is born demoted. The nightly stage repairs it deterministically from a recognized `Source`, through the bulk-write scope (bounds T-20, extends T-7/T-8)
- Content commitment on the read path (`MemoryCommitment`, #80) — a memory id IS a truncated SHA256 over its own content, so `Check` re-derives it and `MemoryTrust.Factor` multiplies by the result *after* the echo lift; echoes can never launder a rewrite, and the only sanctioned repair is supersession (a fresh id). `Kind` is normalized inside `MemoryIdGenerator.Generate` so writer and verifier agree by construction. Redaction is authorized STRUCTURALLY via the one `Render`/`IsAmendment` shape — no per-verb allowlist — and that shape carries no knowledge, so forging it destroys the payload. De-boosts and reports; never hides (#37 downrank-never-hide) (bounds T-15)
- Realized-benefit ROI gate (`MemoryRoi`, MemoryRoi.cs) — reversible, derived recall de-boost + `RoiDecay` Importance demotion for proven net-negative action memories; never forgets, content untouched, recoverable by a single echo (bounds T-9)
- Consolidation provenance carry-through (`ProvenanceRules.ForContributors`, shared by ConsolidationEngine + the Canon mint adapter) — prevents laundering a poisoned source into a trusted insight or Canon page
- Canon curation gate (`CanonService`, `ICanonMintPort`, #75) — drafts live in `canondrafts/*` and reach `memories/*` only on Approve through the full write gate; the minted page carries anti-laundering provenance + `DerivedFrom` citations; consolidation/dedup skip `canon:*` pages (`CanonTags.IsCanonPage`); draft prose is secret-scanned at creation and render-trust-gated (escaped) in the Web UI (bounds T-18, T-19)
- Reflector anti-laundering (ReflectionEngine.cs) — the corpus's only LLM-driven write ships dormant, stamps all trust-bearing fields engine-side (never model-owned), floats new `Reflection`-provenance memories at the provisional 0.5 trust floor, carries through the least-trusted contributor's provenance, and runs the full `WriteValidator` secret+signal gate on the synthesized text (bounds T-14)
- Git-history intake gating (`GitHistoryExtractor`) — deterministic zero-LLM allowlist + per-candidate write gate + provisional `Intake` trust floor, so commit-derived content cannot be born trusted (bounds T-16)
- Polarity guards (`ValencePolarity`, Valence feature) — a `Refuting` claim can no longer be silently collapsed into the `Affirming` claim it contradicts at the store dup-gate, dedup, or consolidation, closing a latent *integrity* defect where contradicting memories corrupted each other; the stance-conflict check is the compensating control the new negative-knowledge surface rides on (T-13)
- Write-time conflict quarantine (`ConflictGate`, `QuarantineInfo`, #37) — a hard-stance store that near-duplicates and contradicts a high-trust incumbent is quarantined (heavy recall de-boost, never hidden so it can earn the echo that clears it) instead of silently stored; an explicit supersession is exempt; an echo clears the verdict and a one-edit `Released` flag reverses a false positive (bounds T-6, T-7, T-13)
- Derived-field hygiene at the derivation point (`EntityExtractor.Extract` → `EntityHygiene`) — a repair that cleans a *derived* field is only durable if every deriver produces the clean form; otherwise the two stages undo each other indefinitely. This is what made the v1.19 entity-hygiene cleanup non-durable: corpus repair dropped the noise, the enrichment backfill re-derived it from the same content, and both reported `Affected: 1` on every pass while a whole-repo diff showed zero documents changed. Non-zero stage counts are therefore not evidence a repair persisted (bounds the durability of the v1.19 chain-of-thought scrub)
- Pass-scoped entry identity (`SharedEntryStore`, maintenance) — one object per memory for a whole maintenance pass, so a repair written by an early stage cannot be reverted by a later stage's stale whole-document write. Stages read overlapping index-backed pages and write whole entries, so a late writer's copy predates an early stage's write and silently reverts it. Closed structurally rather than per stage, and the completeness of the delegation is asserted by reflection rather than trusted; the hazard is proven by test rather than observed in the field (bounds the durability of every stage-owned repair, incl. T-20's provenance relabel)
- Poison-pattern log (`IPoisonLog`, `poisonpatterns/*`, #37) — append-only, no-decay record of contradiction attempts keyed by content fingerprint; a repeat attempt fast-paths to Rejected and the evidence ("what keeps coming back, and against what") survives restarts
- Backup SHA256 checksum verification
- API key scopes restrict write access
- Quality dashboard detects low-confidence and conflicting memories

- RavenDB access via strongly-typed LINQ API (no injection)
- System.Text.Json for serialization (no type-based deserialization attacks)

### 2.7 Memory-Lifecycle Security Taxonomy

The STRIDE tables above are categorized by attacker action. Because Eidet's core asset is a *memory* that flows through a lifecycle, this taxonomy cross-cuts that view: the 6-phase × 4-objective grid from the Mnemonic Sovereignty survey (arXiv:2604.16548) maps where each security objective is enforced as a memory moves from ingestion to sharing. It exists to surface gaps — a blank cell is an unguarded phase/objective pair.

Objectives: **Confidentiality** (who may read it), **Integrity** (it is not tampered with), **Availability** (it survives and is retrievable), **Provenance** (its origin and trust are known and honest).

| Phase | Confidentiality | Integrity | Availability | Provenance |
|-------|-----------------|-----------|--------------|------------|
| **Ingest** | SecretScanner blocks credential storage — per candidate in the intake sink for file + git intake (#63 closed); API scopes gate writes | SignalGate rejects low-signal content; strongly-typed deserialization; write-time `ConflictGate` quarantines a hard-stance store contradicting a high-trust incumbent *(T-6/T-13)* | — | `MemoryProvenance` stamped on every write; pack/intake tagged at the import surface; **closed-world default** — an unrecognized `source` or unparseable value resolves to `Unknown`, never to a trusted origin *(T-20)* |
| **Store** | OS file permissions on RavenDB data dir; localhost-only binding | Append-only model with validity intervals | Maintenance TTL + retention; backups | Provenance + `Source` + `DerivedFrom` persisted; never mutated in place |
| **Retrieve** | API key scopes on read endpoints | Non-local de-boost (0.8×) on mounted layers; reversible ROI de-boost of proven net-negative action memories *(T-9)*; heavy quarantine de-boost of contradicting memories, cleared by an echo *(T-6/T-13)*; **content commitment re-derived per recall** — content rewritten under a live id is held at 0.25, applied after the echo lift so echoes cannot launder it *(T-15)* | Hybrid lexical+vector recall; type budgets | **Trust tier (`MemoryTrust`) gates retrieval weight** — pack, intake, and procedure/heuristic all held provisional until echoed, on three tiers (import 0.5 / intake 0.7 / first-party 1.0); unestablished provenance shares the *import* floor, never the intake one *(T-7, T-20)* |
| **Consolidate** | Runs in-process, no new exposure | Dedup + supersession chains; polarity guards keep contradicting (Affirming↔Refuting) memories from collapsing into one *(T-13)*; supersession (a fresh id) is the ONLY sanctioned content repair, so a correction re-commits rather than rewriting under the old id *(T-15)* | Importance boost keeps salient insights alive | **Provenance carry-through** — untrusted sources cannot launder into a trusted insight; boost admits trusted sources only; `Unknown` fails `IsTrusted`, so a synthesis over legacy memories is born demoted *(T-20)* |
| **Forget** | Soft-delete hides content from recall | Forget audit observation with reason + `DerivedFrom`; **runtime post-forget verification (`IntegrityAuditor`) asserts absence from every read path** *(R-2)*, extended to LIVE memories' own claims — established provenance, intact content commitment, citations that still resolve *(T-15, T-20)*; structured `ForgetReason` causes (TTL / dedup / budget-eviction / deprecated) make "why is this gone?" answerable *(#39)* | Soft-delete preserves history (recoverable); budget/deprecate evictions are reversible soft-deletes, config-gated | Audit trail records who/why; version chain via `eidet_history` |
| **Share** | Packs are read-only layers; no auto-share | No pack signature verification *(residual — T-1)* | Pack export/import portability | Provenance survives export (markdown frontmatter); imported packs stay provisional via trust tier; `Unknown` is never emitted, so a foreign install applies its own default rather than inheriting ours *(T-20)* |

Known gaps (tracked above): no pack signature verification (T-1, T-7 attack surface), no per-request read audit (R-1), no encryption at rest for backups (I-4). **Loose ends sit outside this taxonomy entirely** — they are open-work items, not memories, and bypass the signal gate, provenance/trust tier, decay, and consolidation by design; the only lifecycle controls they get are the park-time secret scan and the promote-time re-entry into the full write gate (T-10, D-6). **Memory-tool files likewise sit outside it by design** — they are faithful scratch blobs, not memories; their lifecycle controls are the write-time secret scan + size cap, `MemoryPath` scoping, and the opt-in `IMemoryBridge` promotion path, which re-enters the full write gate (T-17, I-9, D-7).

### 3.2 Residual Risks

- **No TLS termination**: Eidet uses HTTP only. Deployments beyond localhost require a reverse proxy (nginx, Caddy, Cloudflared) for TLS. Startup log shows bind address so the user is aware.
- **Config file as trust anchor**: Many threats reduce to "attacker can modify config.json." This is accepted — an attacker with that access already has full user-level system compromise.
- **No request audit log**: Cannot investigate after-the-fact who accessed what data.
- **Pack file integrity**: .eidet pack files have no cryptographic verification, allowing memory injection if attacker can place files.
- **Secret scanner coverage**: Regex-based patterns can be evaded with obfuscation, encoding, or unknown token formats. A secret that slips past (or is later reclassified) can now be hard-erased from history with `RedactAsync` (#65), so this residual has a remediation path rather than being permanent.
- **Trust is a de-boost, not a cutoff**: `MemoryTrust`/`MemoryRoi`/quarantine multiply scores down but no absolute threshold excludes a candidate — in small result pools a heavily de-boosted poisoned memory can still rank in (T-7, T-12 residual). The #37 quarantine de-boost is deliberately non-zero (a hidden memory could never earn the echo that clears a false positive), so it narrows but does not eliminate this for the contradiction case. The #80 commitment factor is the same shape deliberately: a `Broken` commitment caps a memory at 0.25 and raises a Critical `commitment-broken` finding, but it **de-boosts and reports, never hides** (#37 downrank-never-hide) — so tampered content stays reachable in a small pool, by design, and the dashboard rather than the ranker is what makes it actionable.
- **Loose ends outside the memory lifecycle**: no trust tier, no decay, no write-side caps; read-side caps and the park-time secret scan are the only controls (T-10, D-6).
- **MCP stdio is unauthenticated**: `ApiAuthGate` wraps HTTP only; the stdio transport relies entirely on OS process trust (acceptable for the launched-by-client model, but worth remembering when auth is treated as the control).
